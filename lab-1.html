Раздел 3.1.1 · Лабораторная работа № 1

Архивирование и восстановление данных

Открыть PDF

Цель работы: Изучение основных методов резервного копирования и восстановления информации. Освоение практических навыков системного администрирования при ликвидации последствий аварий и сбоев в распределенных информационных системах.

Программное обеспечение: Эмулятор СУБД SQLServer2000Emu.exe.

Краткие теоретические положения

Резервное копирование (архивирование) данных решает две задачи: долговременное хранение неизменяемых системных файлов и оперативная защита динамически обновляемых данных. Логической единицей работы и восстановления в реляционной СУБД выступает транзакция — атомарная совокупность команд Transact-SQL, которая либо выполняется целиком, либо полностью отменяется (откатывается) с сохранением целостности данных.

Типы резервного копирования:

  • Полное архивирование: копирование всех файлов распределенной базы данных с фиксацией архивного бита. Служит базовой отправной точкой для любых восстановительных сценариев.
  • Дифференциальное (добавочное) архивирование: копирование только тех изменений и страниц данных, которые были модифицированы с момента последнего полного сохранения.
  • Архивирование журнала транзакций: сохранение непрерывной цепочки журнальных записей всех выполненных операций, обеспечивающее восстановление СУБД на любой момент времени вплоть до секунды системной аварии.

Порядок выполнения работы

  1. Запустить файл SQLServer2000Emu.exe и нажать кнопку «Начать» для инициализации главного окна программы.
  2. В меню «Файл» → «Создание Базы данных» создать исходную распределенную базу данных. В названии базы указать номер группы и номер бригады (например, Database035_02).
  3. Сформировать структуру распределенной БД: сгенерировать файлы данных, распределенные по 5 рабочим станциям.
  4. В пункте меню «Выполнение транзакций» внести исходный пакет изменений (число транзакций задать равным 15 + N, где N — номер варианта бригады).
  5. В меню «Работа» → «Новое устройство резервного копирования» зарегистрировать файл на диске в качестве архивного носителя.
  6. Создать полную резервную копию базы данных через стандартный пункт копирования. Просмотреть структуру архива в разделе «Просмотр».
  7. Сгенерировать дополнительный пакет транзакций (10 + N транзакций).
  8. С помощью мастера копирования создать дифференциальную резервную копию базы данных. Зафиксировать перечень изменений.
  9. Внести очередную серию изменений в базу данных (10 + N транзакций).
  10. Создать новое архивное устройство и сохранить на него резервную копию журнала транзакций.
  11. Внести финальные изменения (5 + N транзакций), зафиксировать их параметры и смоделировать аварийный сбой системы.
  12. В меню «Работа» → «Восстановление Базы данных» выполнить последовательное восстановление данных: сначала из полной копии, затем из дифференциальной копии и, наконец, из журнала транзакций.
  13. Через пункт «Ввод транзакций вручную» внести незафиксированные в копиях транзакции, чтобы привести базу к актуальному виду на момент сбоя. Проверить корректность восстановления.
