Раздел 3 · Лекции 6 ч

1. Служба динамической конфигурации хостов (DHCP)

Протокол DHCP (RFC 2131) реализует централизованное автоматическое назначение IP-параметров узлам локальной сети, исключая дублирование адресов. Функционирует по модели клиент-сервер на базе транспортного протокола UDP (порт 67 для сервера, порт 68 для клиента).

Способы назначения IP-адресов в стандарте DHCP:

  • Ручное назначение: администратор сопоставляет статический IP-адрес с конкретным физическим MAC-адресом сетевой карты хоста.
  • Автоматическое назначение: сервер единожды выделяет клиенту постоянный IP-адрес из диапазона без ограничения срока аренды.
  • Динамическое назначение: клиенту предоставляется временный IP-адрес из пула (Scope) на регламентированный срок аренды (Lease Time).

Четырехшаговый цикл DORA:

  1. DHCPDISCOVER: клиент рассылает широковещательный датаграммный пакет (255.255.255.255:67) для обнаружения активных серверов.
  2. DHCPOFFER: сервер резервирует адрес из пула и отправляет клиенту сетевые опции (IP, маска, шлюз по умолчанию).
  3. DHCPREQUEST: клиент подтверждает выбор предложенного IP широковещательно, уведомляя остальные серверы об отмене брони.
  4. DHCPACK: выбранный сервер заносит связку MAC-IP в постоянную базу и подтверждает аренду узлу.

2. Служба доменных имен (DNS) и разрешение адресов

DNS (RFC 1035) — распределенная иерархическая база данных, реализующая сопоставление символических доменных имен узлов (FQDN) с сетевыми IP-адресами. Пространство имен организовано в виде инвертированного дерева с вершиной в виде корневого домена (root domain «.»).

Механизмы прямого и обратного разрешения:

  • Прямое разрешение: нахождение 32-битного IPv4 адреса по доменному имени узла через ресурсные записи типа A.
  • Обратное разрешение: поиск FQDN по IP-адресу через служебный домен in-addr.arpa с записью типа PTR. Порядок октетов адреса в зоне инвертируется (например, для узла 192.168.10.5 создается запись 5.10.168.192.in-addr.arpa).
  • Рекурсивный и итеративный опрос: при рекурсии сервер берет на себя весь опрос цепочки серверов; при итерации — возвращает клиенту ссылку на вышестоящий авторитетный сервер.
Раздел 5 · Лекции 4 ч

3. Безопасность ИС, политики доступа и протокол Kerberos

Безопасность корпоративной сети базируется на разграничении прав учетных записей (пользователи и группы безопасности) и криптографической аутентификации.

Аутентификация по протоколу Kerberos v5:

Протокол Kerberos использует службу распределения ключей (KDC) и сеансовые билеты, исключая передачу открытых паролей в сетевом трафике:

  1. Клиент отправляет запрос к KDC и получает зашифрованный билет TGT (Ticket-Granting Ticket).
  2. Для доступа к конкретному серверу клиент предъявляет билет TGT службе выдачи билетов TGS.
  3. Служба TGS генерирует сеансовый билет (Session Ticket) с сеансовым ключом для связи между клиентом и целевым сервером.
Раздел 7 · Лекции 3 ч

4. Стратегии резервного копирования и восстановления данных

Для предотвращения потерь информации при системных сбоях и авариях применяются регламентированные схемы архивации баз данных:

  • Полное резервное копирование: сохранение всех файлов базы данных с установкой архивного бита.
  • Дифференциальное (добавочное): копирование только тех страниц и файлов, которые изменились со времени последнего полного архивирования.
  • Резервная копия журнала транзакций: фиксация логически завершенных блоков транзакций SQL, позволяющая восстановить состояние СУБД вплоть до момента сбоя.
