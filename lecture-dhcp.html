Служба DHCP и ее компоненты

Протокол динамической конфигурации хостов (Dynamic Host Configuration Protocol) обеспечивает автоматизированное распределение параметров стека TCP/IP, предотвращая конфликты адресации и снижая трудоемкость сопровождения сети.

1. Назначение и архитектура службы DHCP

Служба DHCP функционирует по классической модели клиент-сервер на базе транспортного протокола UDP. Сервер ожидает входящие запросы на порту 67, а клиенты принимают ответы на порту 68. Применение службы исключает необходимость ручного ввода IP-адресов на каждом узле и централизованно передает параметры маршрутизации.

Способы назначения IP-адресов в стандарте DHCP:

  • Ручное назначение: администратор сопоставляет конкретный IP-адрес со статическим аппаратным MAC-адресом сетевого адаптера клиента в таблице резервирования (Reservations). Применяется для серверов, сетевых принтеров и маршрутизаторов.
  • Автоматическое назначение: сервер единожды выделяет клиенту постоянный свободный IP-адрес из настроенного диапазона без ограничения срока аренды.
  • Динамическое назначение: сервер предоставляет клиенту IP-адрес во временное владение на правах аренды (Lease Time). По истечении срока адрес возвращается в пул, если аренда не была продлена.

2. Процедура выделения адреса (Цикл DORA)

Процесс получения параметров узлом включает четыре последовательных шага обмена датаграммами:

  1. DHCPDISCOVER: клиент рассылает широковещательный пакет (Broadcast) с адреса 0.0.0.0:68 на адрес 255.255.255.255:67 для обнаружения доступных серверов в локальном широковещательном домене.
  2. DHCPOFFER: серверы, принявшие запрос, временно резервируют свободный адрес из настроенного пула и направляют клиенту предложение с параметрами маски и срока аренды.
  3. DHCPREQUEST: клиент выбирает одно из поступивших предложений и широковещательно информирует сеть о своем выборе. Это уведомляет выбранный сервер о согласии, а сторонние серверы — о снятии временных броней.
  4. DHCPACK: выбранный сервер заносит связку MAC-IP в постоянную базу данных и отправляет подтверждающий пакет клиенту с заполнением всех необходимых опций.

3. Области действия (Scope) и авторизация серверов

Область действия тесно связана с физической топологией сети. Создавая область, администратор определяет начальный и конечный адреса пула, маску подсети, срок аренды и диапазон исключений (Exclusions) для устройств со статическими адресами.

В крупных сетях на базе Active Directory обязательно применяется процедура авторизации сервера DHCP. Работа службы разрешается только на тех серверах, IP-адреса которых внесены в глобальный каталог администратором домена. Неавторизованный («поддельный») сервер автоматически блокируется и останавливает выдачу адресов.

4. Таймеры продления аренды (T1 и T2)

Для предотвращения разрыва сетевых соединений клиент инициирует процедуру продления аренды:

  • Таймер T1 (50% срока аренды): клиент отправляет одноадресный запрос DHCPREQUEST напрямую выдавшему серверу. При успешном ответе DHCPACK срок аренды сбрасывается.
  • Таймер T2 (87.5% срока аренды): если сервер не ответил, клиент переходит в аварийный режим и рассылает широковещательные запросы DHCPREQUEST ко всем серверам сети для продления аренды у любого доступного узла.
